Leakage Validation
==================

These checks validate the generated split artifacts; they cannot prove that the source datasets are free from semantic leakage.
Feature selection is performed on training data only in scripts/select_and_split.py.
Repeated encoded feature combinations are reported separately from repeated combinations with conflicting targets.

PASS: exam_score - target absent from features
REVIEW: exam_score - train/validation exact feature overlap (count: 1)
REVIEW: exam_score - train/validation conflicting targets for shared features (count: 1)
REVIEW: exam_score - train/test exact feature overlap (count: 1)
PASS: exam_score - train/test conflicting targets for shared features (count: 0)
PASS: exam_score - validation/test exact feature overlap (count: 0)
PASS: exam_score - validation/test conflicting targets for shared features (count: 0)
PASS: placement - target absent from features
PASS: placement - train/validation exact feature overlap (count: 0)
PASS: placement - train/validation conflicting targets for shared features (count: 0)
PASS: placement - train/test exact feature overlap (count: 0)
PASS: placement - train/test conflicting targets for shared features (count: 0)
PASS: placement - validation/test exact feature overlap (count: 0)
PASS: placement - validation/test conflicting targets for shared features (count: 0)

Interpretation:
- Exact feature overlap can occur because encoded features have limited discrete values.
- Conflicting targets for the same feature combination are a stronger warning sign than overlap alone.
- The synthetic row-wise pairing of the two source datasets remains a validity limitation.
- Perfect random-forest placement results should not be treated as proof of real-world performance.
